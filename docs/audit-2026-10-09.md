# Codebase Audit: EnglishMinds_web

Date: 2026-10-09 · Commit: `0082093`

## Context

This repo is not an application codebase. It is a **Claude Design canvas export**: 14 `*.dc.html` design docs plus a generated runtime (`support.js`). The runtime loads React 18.3.1 and Babel standalone 7.29.0 from unpkg and compiles each page's `<script type="text/x-dc">` in the browser. Several pages are **design canvases**, not web pages: `Site v2`, `Grupe`, `Instagram` and `Test` set `design_doc_mode=canvas`. `Site v2` lays out a 1280px desktop artboard and a mobile artboard side by side, with notes such as "Runda 2 · Direcția 1a rafinată".

"Enterprise-grade" is therefore the wrong yardstick. The real question is whether this can ship as the academy's website. As it stands, it cannot.

## 1. Executive Summary

**Health score: 38/100** as a production website. As a design prototype it scores about 75: coherent, small and readable.

Top 3 structural risks:

1. **The prototype is the production artifact.** The pages are canvases with artboards and designer notes, and they compile JSX in the browser via Babel. There is no build, no SEO metadata (no `<title>` or `lang` on any `.dc.html`) and no real responsive layout, because desktop and mobile are separate hand-built copies.
2. **Desktop/mobile duplication.** `Site v2` keeps parallel state (`d`/`m`, `faqD`/`faqM`, `leadD`/`leadM`) and duplicate markup for each artboard. `Grupe` does the same (`tabsD`/`tabsM`). Every content change has to be made twice.
3. **Domain data and contact info copied across files.** The `LEVELS` table exists in 3 variants (Site v2, Grupe, Test's `LV`), the age list in 4, the WhatsApp number `40775630680` in 12+ places, and the inline logo markup in 13 places. These copies have already drifted: the Starters and Flyers descriptions differ between pages.

## 2. Architecture & Modularity Violations

| File | Problem | Fix |
|---|---|---|
| `EnglishMinds Site v2.dc.html` (292 lines, 280 inline `style=`) | God page: canvas chrome, two full artboards, a quiz engine, FAQ and lead form in one file | Split into sections; use one responsive layout instead of two artboards |
| `EnglishMinds Test.dc.html` (161-line script) | Question banks, scoring rules, level mapping, canvas diploma rendering, PDF popup and WhatsApp hand-off in one class | Extract the `questions` data, a pure `scoreTest()`, and `renderDiploma()` |
| `Site v2`, `Grupe` | Do not use `EMHeader`/`EMFooter`; the header and logo are hand-copied (twice in Grupe) | Use `dc-import` consistently; only 4 of 10 site pages do so now |
| `EMHeader.dc.html:22` | The `active` prop enum is `[acasa,cursuri,metoda,tabere,blog]`, but the links (and Test's `active="test"`) use `test` | Add `test` to the options |
| `EMHeader`, `index.html` | "Home" points to the `Site v2` **canvas**; the root redirects to the internal project `Index` (status board: "Gata / În lucru") | Make the public root the real homepage; keep the project index private |
| Global | No shared constants for colors or contact details. `#14224a` appears 182×, `#ffc41f` 112×, `#c4501a` 97× | CSS custom properties plus one `site.js` config (phone, address, Instagram, levels) |

There are no circular dependencies, because there is barely any dependency graph. The domain is not isolated anywhere; data lives inline in the views.

## 3. Code Quality & Anti-Pattern Report

- **No AI-comment noise.** The page scripts are terse, with no `// set value` comments. `support.js` is generated (its header says "do not edit") and is out of audit scope.
- **Cryptic naming** over-corrects the other way: `QS`, `G`, `ST`, `SK`, `SKC`, `LV`, `OFF`, `x` (the canvas context), `q.h/t/o/a/e`. For questions, `{h,t,o,a,e}` should become `{hint,text,options,answer,explain}`.
- **Swallowed errors:** `try { window.open(...) } catch (e) {}` appears 4 times. `window.open` does not throw when no popup opens; it returns `null`. The catch is therefore dead, and the real failure (popup blocked, user gets nothing) still sets `sent: true`.
- **Self-XSS in `Test.dc.html` `downloadPdf`:** `r.childName` (user input) is interpolated unescaped into `w.document.write` (`<title>Diplomă ${r.childName}</title>`). The impact is low, since it only reaches the same user, but the value should be escaped or the page built with the DOM.
- **Styling copied, not shared:** about 1,000 inline `style=` attributes and no stylesheet. The logo's `clip-path` star polygon is pasted 13 times.
- **Placeholders that would ship:** `Grupe` FACTS contains `[de completat]`, `[nr.] copii`, `[manual Cambridge]` and `[preț] lei / lună`; `Tabere` contains `[preț]`.
- **Duplicated submit logic:** `lead().submit` (Site v2) and `submit` (Lectie Demo) build the same WhatsApp message. Replace both with one `buildDemoMessage({name, phone, age})`.
- **Diploma fonts:** the canvas draws with `Nunito` without awaiting `document.fonts.ready`, so the first download can render in the fallback font.

## 4. View & Component Breakdown

- **Presentation vs. logic:** `renderVals()` mixes view styling (it returns `bg`/`fg` hex values) with business rules (scoring, level mapping). The views are not "dumb": colors for the selected state are computed in JS instead of a CSS class or `aria-pressed` styling.
- **State:** this is local class state, so there is no prop-drilling. `Site v2` holds 6 state slices only because of the two artboards; a single responsive view halves that.
- **Business rules buried in the UI:** the level mapping in `Test.result()` (`pct >= .85 ? 'Pre A1' : ...`) is a nested ternary chain over magic thresholds. It should be a data table plus a pure function.
- **Two different quizzes:** `Site v2` has a 5-question mini quiz with its own ±1 level heuristic, and `Test` has the full test with different thresholds. A parent can get different recommendations from each.
- **Accessibility:** interactive elements are real `<button>`s (good), but:
  - Inputs have no `<label>` or `aria-label`.
  - FAQ toggles lack `aria-expanded`.
  - The selected state is shown by color only.
  - The audio questions depend on `speechSynthesis` with a silent `catch`. Where speech synthesis is unavailable, the question cannot be answered and there is no fallback text.

## 5. Test Suite & Coverage Assessment

**There are no tests at all**: no unit, integration or E2E tests, no CI, no lint, no `package.json`. The untested logic carrying the most risk:

- `Test.result()` level mapping, especially boundary values (`pct` exactly at .4, .5, .7, .8, .85, .9) and a skill with 0 questions (handled in code, but unverified).
- The `Site v2` quiz clamp `Math.max(0, Math.min(4, li))`, with `base` at 0 or 4 and a score of 0, 1 or 5.
- Name/phone validation: whitespace-only input is caught, but there is no phone format check at all.
- Popup blocked: the user is told the message was sent when nothing opened.
- Diploma name overflow loop: the font size stops shrinking at 50px, so a long name still overflows.

## 6. Actionable Refactoring Roadmap

### P0: decide what this repo is (blockers only if it is going live)

1. Treat the `.dc.html` files as design specs. Build the production site separately with a static site generator (Astro or 11ty) or plain HTML+CSS. A brochure site does not need Babel or React at runtime.
2. Use one responsive layout per page; delete the artboard and canvas chrome.
3. Fill in or remove every `[placeholder]`. Add `<title>`, a meta description and `lang="ro"`.
4. Point the public root at the homepage, not the project status board.

### P1: deduplicate

5. Add a `site.config.js` for contact details, `LEVELS` (one source, including descriptions) and `AGES`.
6. Define design tokens as CSS variables (`--navy:#14224a`, `--sun:#ffc41f`, `--rust:#c4501a`, `--orange:#ec6423`, `--cream:#fff5e6`), and replace the inline styles with a stylesheet.
7. Create shared partials: header, footer, logo, WhatsApp CTA, lead form.
8. Extract `scoreTest(bank, answers, mode, choice)` and `recommendLevel()` as pure modules, and make the mini quiz call the same function.

### P2: harden

9. Add Vitest unit tests for the scoring and level mapping (table-driven boundary cases) and for the message builder.
10. Add a Playwright smoke test covering:
    - the test flow through to the result and the WhatsApp link (assert the URL; do not open it);
    - the lead form's empty and whitespace-only validation;
    - the fallback when the popup is blocked.
11. Accessibility: labels, `aria-expanded`/`aria-pressed`, a text fallback for audio questions, focus states.
12. Fixes:
    - escape `childName` in the PDF popup;
    - `await document.fonts.ready` before drawing the diploma;
    - handle `window.open` returning `null`;
    - compress `teacher-ema.jpg` (212 KB) and serve WebP or AVIF.

## Open question

One open question decides the P0 path: are these pages meant to be deployed as-is, or are they the design handoff for a site still to be built?
